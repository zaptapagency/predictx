# Model Management Dashboard Guide

## Overview

The Model Management Dashboard provides a complete interface for training, monitoring, and managing ML models. It offers real-time visibility into model performance, predictions, and outcomes.

## Features

### 1. Models Overview Tab
View all models at a glance with key metrics and status indicators.

**What You See**
- Model name and type (churn, opportunity, expansion, health)
- Current status (draft, training, active, failed)
- Performance metrics:
  - **Accuracy**: % of predictions correct
  - **F1 Score**: Balance of precision & recall
  - **AUC-ROC**: Model discrimination ability (0.5=random, 1.0=perfect)
- Features count: How many inputs the model uses
- Last trained date
- **Drift warning**: ⚠️ if model has drifted

**Actions**
- Click any model card to select it and view details
- Filter by model type (churn, opportunity, expansion, health)
- Train new model with "+ Train New Model" button

**Color Coding**
- Green: Model is healthy and active
- Yellow: Model is currently training
- Gray: Model is in draft (not ready)
- Red: Model training failed

### 2. Details Tab
Deep dive into selected model's performance and configuration.

**Sections**

**Performance Metrics**
- Accuracy: Overall correctness
- Precision: Of predicted positives, how many were correct?
- Recall: Of actual positives, how many did we find?
- F1 Score: Harmonic mean of precision and recall
- AUC-ROC: Area under receiver operating characteristic curve

*Interpretation:*
- Accuracy 80%, Precision 85%, Recall 75% = Good model
- High precision, low recall = Misses true cases
- Low precision, high recall = Too many false alarms

**Training Data**
- Period: Date range used for training
- Records: Number of examples in training set
- Training date: When this model was trained

**Model Health**
- Status: Current state
- Drift detected: Whether input distribution changed
- Features: How many features used
- Algorithm: Which ML algorithm (XGBoost, Random Forest, etc)

**Top Features by Importance**
Visual ranking of which features matter most in predictions.

*Example:*
```
days_since_last_login     ████████░░ 23%
mrr_declining             ███████░░░ 19%
renewal_overdue           ██████░░░░ 15%
```

The longer the bar, the more influential the feature.

### 3. Predictions Tab
View predictions generated by the model.

**Columns**
- **Customer ID**: Who was scored
- **Score**: Prediction value (0-1 for churn models)
- **Risk Level**: low/medium/high/critical
- **Confidence**: How certain is the model? (0-100%)
- **Action**: Recommended next step
- **Outcome**: ✅ if outcome recorded, ⏳ if pending
- **Time**: When prediction was made

**Reading the Table**

```
ACME-001 | 0.82 | HIGH | 91% | immediate_outreach | ✅ | Aug 22
```
- ACME-001 has 82% churn risk
- Model is 91% confident
- Outcome has been recorded

**Use Cases**
- Review recent predictions
- Check if predictions have outcomes
- Identify which customers were scored
- Audit prediction quality

### 4. Training Tab
View complete training history and performance over time.

**For Each Training Run**

```
Run #42 - Aug 22, 2026 10:30 AM ✅ success
├─ Duration: 145 seconds
├─ Records: 2,543
├─ Metrics:
│  ├─ Accuracy: 78.43%
│  ├─ Precision: 76.89%
│  ├─ Recall: 80.23%
│  └─ F1 Score: 78.52%
```

**What This Means**
- Each run trained the model on a dataset
- 145 seconds = Model trained quickly
- 2,543 records = Good sized training set
- Metrics improved = Model is learning

**Spotting Problems**

Accuracy declining over runs? Consider:
- Data changed (feature drift)
- Business rules changed
- Need to retrain with newer data
- Check "is_drifted" flag

### 5. Features Tab
Complete catalog of features used in model.

**For Each Feature**

```

├─ Type: numeric
├─ Source: billing.mrr
├─ Description: Monthly recurring revenue
└─ Statistics
   ├─ Mean: $12,543
```

**Use Cases**
- Understand what data feeds models

**Feature Types**

## How to Use: Step by Step

### Training Your First Model

1. **Click "Train New Model"** button
   
2. **Fill in the form**
   ```
   Model Name: Churn Risk Model v1
   Model Type: Churn
   Algorithm: XGBoost
   Training Start: Jan 1, 2024
   Training End: Jun 30, 2026
   ```

3. **Click "Start Training"**
   - Model appears in list with "training" status
   - Training happens in background
   - Dashboard updates when complete

4. **Monitor Progress**
   - Models tab shows status changing: training → active
   - Check Training tab for performance metrics
   - Takes 1-10 minutes depending on data size

5. **Review Results**
   - Click model card to view details
   - Check accuracy, precision, recall metrics
   - Look at feature importance
   - Verify makes sense for your business

### Making Predictions

**Once model is ACTIVE:**

1. **Single Prediction** (in code)
   ```bash
   POST /api/predictions/predict
   {
     "model_id": 1,
     "customer_id": "ACME-001"
   }
   ```

2. **Batch Predictions** (score all customers)
   ```bash
   POST /api/predictions/batch-predict
   {
     "model_id": 1
   }
   ```

3. **View Predictions**
   - Switch to "Predictions" tab
   - See all scored customers
   - Review scores and recommended actions
   - Track which have outcomes

### Recording Outcomes

When customer result is known:

```bash
POST /api/predictions/predictions/42/outcome
{
  "outcome_type": "churn",
  "notes": "Customer did not renew"
}
```

This closes the feedback loop for continuous learning.

### Monitoring Model Drift

**Drift = Model's world is changing**

Red flag: "Drift Detected" warning on model card

What to do:
1. Retrain model with recent data
2. Compare new accuracy to old model
3. If better, deploy new model
4. If worse, investigate what changed

## Understanding the Metrics

### Accuracy
**What**: % of predictions correct
**Range**: 0-100%
**Good**: 75%+
**Example**: 80% = 8 out of 10 predictions correct

### Precision
**What**: Of customers we predicted will churn, how many actually churned?
**Range**: 0-100%
**Good**: 75%+
**Use**: Avoid false alarms to CSM team

**Example**:
- Predicted 100 customers at risk
- 80 actually churned
- Precision: 80%

### Recall
**What**: Of customers who actually churned, how many did we catch?
**Range**: 0-100%
**Good**: 70%+
**Use**: Don't miss at-risk customers

**Example**:
- 125 customers actually churned
- Model caught 100 of them
- Recall: 80%

### F1 Score
**What**: Balanced metric combining precision and recall
**Range**: 0-100%
**Good**: 75%+
**Use**: Overall model quality when both matter

### AUC-ROC
**What**: How well does model rank customers by risk?
**Range**: 0-1 (shown as 0-100%)
**Good**: 0.75+
**Interpretation**:
- 0.5 = Random guessing
- 0.7 = Good model
- 0.85 = Excellent model
- 1.0 = Perfect predictions

## Best Practices

### Model Training

**✅ DO**
- Train on 2+ years of historical data
- Use 70/30 train/test split minimum
- Retrain monthly or when drift detected
- Start with baseline (logistic regression)
- Gradually add complexity (XGBoost)

**❌ DON'T**
- Train on < 50 samples (too small)
- Use only recent data (lose patterns)
- Train on corrupted data (GIGO)
- Ignore drift warnings
- Keep non-performing models active

### Monitoring

**✅ DO**
- Check accuracy weekly
- Track feature drift
- Record outcomes for all predictions
- Compare to baseline model
- Version your models

**❌ DON'T**
- Ignore drift warnings
- Deploy without testing
- Stop recording outcomes
- Train once and forget
- Mix different model versions

### Production

**✅ DO**
- Test in draft mode first
- Validate on holdout set
- Monitor predictions post-launch
- Have fallback plan
- Document decisions

**❌ DON'T**
- Go live without testing
- Use single metric to judge
- Change models without notice
- Forget to record outcomes
- Assume accuracy stays constant

## Troubleshooting

### Model Accuracy is Low

**Check:**
1. Training data quality
   - Are outcomes correctly labeled?
   - Is data representative?
   - Any data quality issues?

2. Feature engineering
   - Do features predict outcome?
   - Any missing important features?
   - Are features noisy?

3. Model algorithm
   - Try simpler algorithm (logistic regression)
   - Try more complex (XGBoost)
   - Tune hyperparameters

4. Data size
   - Need 50+ samples minimum
   - Ideal: 500+ samples
   - More data = better accuracy

### Model Shows Drift

**Causes:**
1. Business changed (different customer types)
2. Your product changed (new features, pricing)
3. Market changed (new competitors)
4. Seasonal patterns

**Solutions:**
1. Retrain model with recent data
2. Compare new model accuracy to old
3. If better, deploy new model
4. If worse, investigate root cause
5. Add new features if needed

### Predictions Not Triggering Workflows

**Check:**
1. Is model in ACTIVE status?
2. Did prediction score exceed threshold?
3. Is workflow in ACTIVE status?
4. Are conditions blocking execution?
5. Check workflow logs for errors

### Feature Not Available

**Cause**: Raw data field doesn't exist

**Solutions:**
1. Verify data is being synced
2. Check connector status
3. Make sure field name matches
4. Run sync to refresh data
5. Retrain model with available features

## FAQ

**Q: How often should I retrain?**
A: Monthly is good. More often if business changes rapidly. Less often if model is stable.

**Q: Can I have multiple models?**
A: Yes! Train separate models for churn, opportunity, expansion, health.

**Q: How much training data do I need?**
A: Minimum 50 samples. Ideal 500+. More is better.

**Q: Which algorithm should I use?**
A: Start with logistic regression (fast, interpretable). Graduate to XGBoost (accurate, slower).

**Q: What if my model has low accuracy?**
A: Check data quality, features, and outcome labels. Try more data.

**Q: Can I export predictions?**
A: Yes, via API. See Predictions endpoints.

**Q: What's the prediction latency?**
A: Single prediction: 100-200ms. Batch: 1000/min.

**Q: Can I use custom features?**
A: Yes! Extend FeatureEngineer class in the backend.

**Q: How do I know if model is working?**
A: Record outcomes and measure accuracy over time. Compare to baseline.

**Q: What's "confidence" in predictions?**
A: How certain the model is about its prediction (0-100%).
